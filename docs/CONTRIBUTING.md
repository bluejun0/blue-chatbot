# CONTRIBUTING

## 이슈 작성 및 관리

- 작업은 이슈 단위로 작성합니다.
- 이슈 제목은 `{type}: {한글 제목}` 로 정합니다. ex) feat: FAQ api 구현
- 이슈 본문에는 **목표, 작업범위, 완료조건**을 명시합니다. (부분적으로 생략될 수 있습니다)

## 브랜치 생성 및 관리

- 브랜치는 이슈를 달성/해결하는 작업 단위입니다.
- 하나의 브랜치는 하나의 이슈를 기준으로 합니다.
- 브랜치는 기본적으로 최신 main 에서 분기합니다.
- 브랜치 이름은 `issue/{이슈 번호}-{영문 작업명}`으로 합니다. ex) issue/1-contributing-guidelines
- 머지된 브랜치는 다시는 사용되지 않습니다. 만약 작업 내용에 누락이 있거나, 버그가 있다면 새로운 이슈를 생성하세요.
- `history` 브랜치는 설계 과정, 고민, 대안, 실패와 변경 이유 등을 보존하는 장기 기록 브랜치이며 `main`에 병합하지 않습니다.
- `history` 브랜치의 기록은 별도의 이슈와 PR 없이 직접 커밋하여 누적합니다.

## Pull Request 게시 및 관리

- 하나의 PR은 하나의 브랜치 하나의 이슈에 대응합니다.
- PR의 기본 target 브랜치는 main 입니다.
- PR 제목은 대응되는 이슈의 제목을 그대로 사용합니다.
- PR 본문에는 **작업요약, 주요변경사항, 테스트 결과, 관련 이슈**를 기록합니다.
- 해당 PR로 이슈가 완료되면 `Closes #이슈번호`를 사용합니다.
- 해당 PR로 이슈가 완료될 수 없다면 `Refs #이슈번호`를 사용합니다.
- 코드 수정이 있을 경우에는, Claude의 리뷰를 받고 난 후 머지합니다.
- 기본적으로 스태킹 PR은 사용하지 않습니다. 만약 필요한 경우, 메인테이너와 상의한 후 사용합니다. 상의가 없을 시 복구 없이 closed 될 수 있습니다.
- 머지 방식은 `merge commit`를 사용하고, 메인테이너가 합니다.

## 커밋 규칙

- 커밋 메시지는 `{type}: {한글 요약}`으로 정합니다. ex) feat: FAQ api 구현
- 커밋 메시지 끝에는 끝에 마침표를 사용하지 않습니다.
- 작업 내용이 드러나는 구체적인 표현을 사용합니다.
    - 나쁜 예: fix: 코드 수정
    - 좋은 예: fix: FAQ 결과에서 한글 끼짐 오류 수정
- 하나의 커밋에는 하나의 논리적인 변경만 포함합니다.
- AI 단독으로만 작업한 커밋의 경우 `Generated with ..., Co-authored-by ...` 같은 문구를 표시합니다.
    - ex) 인간이 코딩한 후, 커밋만 AI가 하는 경우, `Generated with ..., Co-authored-by ...` 문구를 적지 않습니다.

## 문서 규칙

> 기본적으로 AI를 위한 규칙이지만, 인간이 작성할 때에도 준수되어야 합니다.
> 만약 현재 CONTRIBUTING.md 문서를 포함해 해당 규칙을 수정하고 싶다면 이슈를 생성후 PR를 생성해주세요.

- 문서는 docs/ 경로 안에 기록합니다.
- **현재 설계에 부합하거나 코드에서 작동하는** 기능, 제약, 의도, 시나리오 등의 문서는 아래와 같이 기록합니다.
    - docs/domain: 현재 시스템의 도메인 개념, 용어, 데이터 모델, 상태와 불변식을 기록합니다. 확정된 현재 설계만 유지하며, 설계 과정이나 폐기된 대안은 포함하지 않습니다.
    - docs/scenarios: 현재 시스템에서 발생할 수 있는 정상, 실패 흐름을 구체적인 사건 순서로 기록합니다.
- **의사가 결정되었지만 아직 구현되거나 완료되지 않은** 결정은 docs/decision에 기록합니다. 위의 "코드에서 작동하는" 조건은 이 경로에 적용되지 않습니다.
    - 정해진 것만 적습니다. 아이디어나 검토 중인 안은 결정이 아니므로 넣지 않습니다. 계획서나 일정표도 아닙니다.
    - 결정을 구현한 PR에서 해당 기록을 지우고, 지운 기록은 history 브랜치에 직접 커밋해 이관합니다. 따라서 docs/decision에는 항상 아직 완료되지 않은 결정만 남습니다.
- 의사 결정 과정에서 발생한 설계 과정, 고민, 대안, 실패와 변경 이유 등의 기록은 **history** 브랜치에 커밋합니다.
